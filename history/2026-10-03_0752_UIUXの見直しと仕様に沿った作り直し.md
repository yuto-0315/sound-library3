## 2. 進め方

1. `document.md`・`追加機能.md` の項目を 1 つずつ、今の実装と照らし合わせた（→ 3 章）
2. 開発サーバーを iPad の大きさ（横向き 1024×768、縦向き 768×1024）で開き、全ページを実際に操作した。
   サーバー（PHP）が無い環境なので、共有ページは `fetch` を差し替えた偽のサーバーで確かめた
3. ページごとに作り直し → 単体テスト → ブラウザで確認 → コミット、をくり返した
   （共通の土台 → API → 音楽づくり → 音あつめ → 音ライブラリ → みんなで共有 の順）
4. すべての CSS について「ほかのページのクラス名と重なって効いてしまう指定」を機械的に洗い出した（→ 4.8）
5. Playwright の E2E テストを新しい画面に合わせ、本物のブラウザ（IndexedDB・MediaRecorder・Web Audio）で確かめた
6. 独立したレビュアー（サブエージェント）3 つに、観点を分けてブランチ全体をレビューさせ、指摘をコードで確かめてから直した（→ 6 章）

## 4. ページごとの変更

### 4.1 共通（`8ba23361`）

- ページを切り替えてもスクロール位置が前のページのままだった（中身は `<main>` の中でスクロールするため）→ 切り替えたら先頭に戻す
- スキップリンクを押すと、HashRouter が `#main-content` をページの URL と解釈して真っ白になった → React に移し、URL を変えずにフォーカスだけ移す
- 存在しない URL でも真っ白 → 音あつめに戻す
- ダークモードの iPad で、一部だけ暗くなって白い背景に白い文字になっていた → 明るい表示に固定（`color-scheme: light`）
- ナビゲーションの `role="menubar"` で、矢印キーで項目が動き、スペースキーでページが切り替わっていた → ふつうのリンクの並び（`aria-current`）
- 指で押しただけでもフォーカスの枠が残り、選ばれていないボタンが選ばれているように見えた → キーボード操作のときだけ枠を出す
- デザインの基本（色・角の丸み・影・ボタン・タグ・入力欄）を `App.css` にまとめた。白い文字を載せる色はコントラスト比 4.5:1 以上、入力欄の枠は 3:1 以上。ホバーの色はホバーできる端末だけ（iPad でタップ後に残らない）
- `npm run start:static` が Express 5 で起動直後に止まっていた。macOS の AirPlay と重なる 5000 番をやめて 5050 番に

### 4.2 API（`480c421f`）

- 先生用ページの楽曲一覧が全員分の楽曲データ（音声入り）を読み込み、サーバーのメモリが足りず何も表示されなかった → 一覧はタイトルと大きさだけ。中身は開くときに 1 曲ずつ
- 誰でも部屋ごと削除できた → 暗証番号（環境変数 `SOUND_LIBRARY_ADMIN_PIN` か、git に入れない `api/admin_pin.php`）。**未設定なら従来どおり**
- 使われていない PUT（誰でも他人の楽曲を書き換えられた）を廃止
- 部屋を削除しても録音ファイルがサーバーに残った → ファイルも消す
- アップロード: 文字数オーバーで DB エラーになりファイルだけ残った／中身が音声でないファイルも保存できた／エラーに SQL の内容が出た → すべて修正。1 ファイル 20MB・1 部屋 1GB まで
- `database/create_database.sql` が JSON 列へのインデックスで途中で止まっていた → 何度でも実行できる形に

### 4.3 音楽づくり（`2bd2f3ec`）

3.1 の表のほか:
- メトロノーム（小節の頭は高い音。書き出しには入れない）
- 上の目盛りを押す・矢印キーで、その位置から再生（`role="slider"`）。再生中はプレイヘッドが見える所までめくる
- 再生中に音を動かしたら予約し直す（以前は再生を押した時の並びのまま鳴った）。音が無いのに再生を押したら案内する（以前は無音が最大 90 秒鳴った）
- 元に戻す／やり直す（ボタン、⌘Z・Ctrl+Z・Ctrl+Y）。テンポの連打は 1 回分にまとめる
- 置いた音をタップして選ぶと「きく」「複製」「削除」（以前の × ボタンは、短い音をつかもうとして消してしまった）
- キーボード: 置いた音を Tab で選び、← → で拍ごと、↑ ↓ で隣のトラックへ、Delete で削除
- 「先生に送る」「使い方」をダイアログに（中央に出る・入力欄にフォーカス・Esc で閉じる・後ろは操作できない・閉じたら元のボタンへ）
- 「ファイルを開く」がキーボードで押せなかった（`display: none` の入力欄を包む label だった）
- テンポ・ズームを何度変えても位置の誤差がたまらない（拍・秒に直して丸めてから掛け直す）

### 4.4 音あつめ（`6de52106`）

- 大きな丸い録音ボタン。録音中は経過時間と残りを出し、**60 秒で自動で止める**（止め忘れて大きな音声ができると古い iPad で重くなる）
- 名前をつける画面: 大きな「きく」と音の長さ、タグの候補、「保存する」「録音しなおす」「この音をすてる」（すてるときは確認。以前の「キャンセル」は 1 回で消えた）
- 「さいきん集めた音」は保存されている音を新しい順に出す（以前はこのページで保存した音だけで、戻ってくると「まだ録音した音がありません」と出て、消えたように見えた）
- マイクを拒否されたら説明を開き、「ページを読み込み直す」ボタンを出す（iOS は読み込み直すまで再び聞いてこない）
- 音の長さを保存する（`measureAudioDuration`。音を出さない `OfflineAudioContext` で測る）
- 録音中のレベルメーターは**付けていない**（古い iPad で録音が不安定になる処理を増やさないため）

### 4.5 音ライブラリ（`6fbee448`）

- ならべかた「新しい順・古い順・名前順・**タグごと**」。タグごとでは、タグが 2 つある音は両方の見出しに出す（入力欄の id が重ならないようにした）。選んだならべかたは次回も使う
- **保存した後でも名前を変えられる**（以前は変えられなかった）。Esc・「やめる」で取り消し、終わったら「名前」ボタンにフォーカスを戻す
- 長さが保存されていない以前の音は、1 つずつ長さを調べて保存する
- 検索でひらがな／カタカナ・全角／半角・大文字／小文字を区別しない（`utils/text.js` の `normalizeForSearch` / `matchesSearch`）
- 削除の確認をカードの中ではなくダイアログに。最初のフォーカスは「キャンセル」
- 失敗は alert ではなく画面内で知らせる。タグの追加候補（ほかの音のタグ）を出す
- 以前は各カードに「DAW ページにドラッグ＆ドロップできます」とあったが、別のページなのでできなかった → 「音楽づくり」ページの「音素材」から使うと 1 か所で案内

### 4.6 みんなで共有（`2dda413f`）

- 「みんなの音」「自分の音を共有する」の 2 つのタブ（矢印キーで切り替え。見えない側の再生は止める）
- みんなの音: 大きな ▶ で試し聞き、つくった人・日付・「N人がもらいました」・タグ、「音ライブラリに入れる」（入れた音は長さも保存）
- **30 秒ごと**と、画面に戻ってきたときに読み込み直す。新しい音はすぐには並べず「新しい音が N こ届きました」を押してから並べる（押そうとしたボタンの位置がずれないように。今ある音の数は新しくする）
- 自分の音を共有する: 試し聞きしながら選ぶ（ラジオボタン）→ 名前とタグ（音ライブラリの値が入る）→「みんなに共有する」。あなたの名前は「先生に送る」と共通で覚えておく。タグは 10 こまで（サーバーと同じ）。20MB を超える音は送る前に案内
- 入力欄の Enter では共有しない（iPad の日本語入力の確定や「改行」でうっかり送らない。確定の Enter は通す）
- 結果は alert ではなく、画面内のお知らせ（`role="status"` / `role="alert"`）

### 4.8 CSS の効きすぎ（`2dda413f`・`ee748c22`）

Create React App はすべてのページの CSS を 1 つにまとめて読み込むので、あるページの CSS の `.tag` や `.search-input` は**ほかのページにも効く**。各 CSS について、指定しているクラス名と、それを使っているほかのファイルを機械的に突き合わせて洗い出した。

| CSS | 効いてしまっていた先 | 症状 |
|:--|:--|:--|
| `CloudPage.css` の `.room-info`・`.search-input`・`.tag`・`.form-group` など | 先生用ページの部屋のカード、音ライブラリの検索欄 | 先生用ページの部屋のカードが横並びに崩れていた ほか |
| `DAWPage.css` の `.sound-info .sound-name` | 音あつめの「さいきん集めた音」 | 長い名前が折り返さず「…」で切れた |
| `DAWPage.css` の `.sound-meta` | 音ライブラリの日付・長さの行 | 右端 15% が薄く消えていた（`mask-image`） |
| `DAWPage.css` の `.no-sounds`・`.sound-actions` | 音ライブラリの「音がありません」とボタンの行 | 文字の大きさ・余白が変わっていた |

ページの CSS はすべて、そのページの一番外の要素（`.cloud-page`・`.sound-library`・`.sound-collection`・`.sound-panel` など）の中だけに効かせる形にした。`App.css`（共通の部品）と `Modal.css`（ダイアログ）は全ページ共通で使う前提。

## 6. レビューと修正

ブランチ全体（`ad25611b..HEAD`）を、観点を分けた 3 つの独立したレビュアー（サブエージェント）に読ませた。
レビュアーには、`api/config.php`（DB の接続情報）・`.env`・暗証番号のファイルを開かないこと、外部と通信しないこと、ファイルを変えないことを指示した。

## 8. デプロイ・移行時の注意

- **画面と API を同じときに更新し、生徒の iPad はページを読み込み直す**
  - 新しい画面は古い API でも動く（部屋番号で探す要求に、古い API は一覧を返すが、同じように探せる。部屋番号を付けた要求も、古い API は無視するだけ）
  - 古い画面のまま新しい API にすると、共有された音の一覧（部屋番号を送らない）が読み込めない。ページを読み込み直せば直る
- 新しいファイル: `api/room_access.php`・`api/admin_status.php`・`database/sample_data.sql`。変わったファイル: `api/rooms.php`・`api/audio.php`・`api/songs.php`・`api/admin_auth.php`・`api/download.php`・`api/admin_pin.example.php`・`database/create_database.sql`
- **DB の変更は不要**（`download_history` の UNIQUE KEY は `main` の SQL から既にある）。`create_database.sql` は何度実行してもよいが、試しの部屋は作らなくなった（手元で試すときは `sample_data.sql`）
- **暗証番号は「半角の英数字・記号で 6 文字以上」**。これより短い値・日本語・例のままの値を設定していると、先生用ページの操作がすべて止まる（SETUP.md）。設定していなければ従来どおり確認しない（先生用ページに注意が出る）
- 部屋の一覧は、暗証番号を設定していれば先生しか見られない。**部屋番号は合言葉**なので、推測されにくい番号を勧める
- `docs/`（GitHub Pages 用のビルド）はこのブランチで作り直した
- 共有ページは、部屋にいて画面が見えている間、30 秒ごとに `audio.php` を読む（1 クラス 30 台で 1 分に 60 回ほど）

### iPad と HTTPS

ブラウザは `http://localhost` 以外の `http://` ではマイクを使わせないため、別のパソコンで動かして iPad から開くと「録音」が使えない。Caddy で HTTPS にし、iPad に一度だけルート証明書を入れて信頼する方法を用意した。確かめる途中で次の 2 つを直した。

- Caddy の自動の「http → https 転送」が、証明書を配る `http://` より優先され、しかもポート番号の無い URL に転送していた → `auto_https disable_redirects`
- IP アドレスで開くとブラウザはサーバー名（SNI）を送らないので、TLS の接続が失敗した → `default_sni`

### 確かめたこと（この Mac で実際に起動。依頼者の了承を得てイメージなどをダウンロードし、終わったあと削除した）

- 3 つのコンテナがすべて healthy になる（`web` はデータベースまで使う API で確かめる）
- 実際の API で: 部屋の作成 → 部屋番号で探す → 音のアップロード（部屋番号が違うと 404、無いと 400）→ 一覧 → 試し聞き（数えない）→ ダウンロード（1 回数える）→ アップロードしたファイルへの直接アクセスは 403 → 楽曲の送信・一覧 → `admin_pin.example.php` は 403、`config.php` は何も出さない
- `.env` の `ADMIN_PIN` で暗証番号が有効になる（一覧は 401、暗証番号付きで 200、生徒の部屋の検索はそのまま使える）
- HTTPS: `https://localhost:8443/` と `https://（IP）:8443/` が、配った証明書を信頼すれば通る
- Playwright の E2E 18 件が、Docker で配信した画面で成功
- 片付け: コンテナ・ボリューム・作ったイメージ・`caddy:2`・ビルドのキャッシュ（5.8GB）を削除。`mysql:8.0` は前からこの Mac にあったので残した

`.bat` は Windows が無いため実行できていない（同じ手順のコマンドを Mac で実行して確かめた）。別の Windows で最初に動かすときは、DOCKER.md の「8. うまくいかないとき」も見てほしい。
